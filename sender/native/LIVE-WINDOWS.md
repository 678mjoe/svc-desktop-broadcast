# Windows 11 x64 原生应用广播

这是独立发送器 ZIP 的操作说明。将整个包解压，再双击 start.cmd。内置运行时通过 WASAPI 读取选定应用。

## 1. 选音源并本机检查

先让播放器播放普通曲目，再进入菜单 **8**。菜单优先列出 Windows 当前的「活动音频会话」，其次列出应用窗口。选播放器名称对应的序号，例如 `1`，有「活动音频会话」的条目优先选。同名条目先单选其中一个。确认单路有电平后，再用 `1,3` 这种形式多选。若应用未出现，从托盘打开它的主窗口并重新进入菜单 8。播放器在选择后重启时，请重新选择。

核对应用名称后输入 START。本机检查报告混合电平，Ctrl+C 停止。暂停全部选中应用时，混合电平应归零，恢复播放后应在同一轮重新显示信号。

若需要排查哪一路有声，可在解压目录的 PowerShell 单独观察菜单显示的 PID。请替换示例数字。

    .\app\svc-wasapi-check.exe check "12345,23456" 30

## 2. 开始直播

1. 让另一名玩家上线并连接 SVC。发送者也先登录游戏，遵循该服对广播者在线状态的要求。
2. 在菜单选 **9**，按当前列表重新选择要广播的应用，再选对应服务器的配对档并输入 START。如果没有配置档，可在游戏内运行 /svcbroadcast pair，复制配对信息，再用菜单 3 完成配对。
3. 等听众确认两款应用都能听到。分别暂停和恢复每款播放器，再暂停两款并播放未选中的第三个应用。确认普通 SVC 交流正常，第三个应用的声音没有混入。
4. 按 Ctrl+C 停播。另开一轮再退出一个所选播放器，确认直播会结束。当前测试版中，任一所选根进程退出会结束会话。

发送者本人会被排除在广播回传之外，由另一名玩家确认听感。菜单选项 4 和 6 仍可用于虚拟设备输入。原生直播也可从 PowerShell 运行，命令会直接开始连接：

    .\send.cmd broadcast-apps --profile my-server --pid 12345 --pid 23456

本轮反馈可填写 TEST-RESULTS-P4C.txt。只分享相关电平日志或错误码。配对串及用户私有配置档请留在本机。

若再次超时，可在日志末尾核对 `heartbeat_age_ms`、`max_clock_step_ms`、`mixed_blocks` 和 `converter_resets`。这些计数帮助区分采集进程不再响应、时间戳停滞和混音不再生成可发送帧。

如果播放器正在播放而电平始终为 `-inf`，请回传菜单中所选条目和日志末尾的一行 `Capture diagnostics`。其中 `signal_packets` 和 `raw_peak_s16` 表示 Windows 交来的非零信号，`placed_signal_packets` 表示信号是否进入对齐缓冲，`pcm_peak_dbfs` 表示最终电平。日志只含计数和电平。
